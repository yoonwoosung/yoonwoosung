어떤 개발자인가

두 개의 팀 프로젝트에서 백엔드를 맡아 설계부터 배포·운영까지 했습니다.

교내 오픈소스 포털 K-OSP는 전임자의 Spring Boot MSA 구조를 인수해 팀장으로 운영하며 칭호, 시즌 랭킹, 이력서 PDF/hwpx 기능을 만들었습니다. 농촌관광 플랫폼 FarmLink에서는 Flask로 TourAPI 연동, 추천 로직, 파일 캐시, 배포 파이프라인을 맡아 ICT이노베이션 충청권 대상을 받았습니다.

AI 코딩 도구로 빠르게 만든 코드가 한 달 뒤 "왜 그렇게 짰는지" 설명되지 않는 순간이 늘어난 뒤로, 선택 이유와 대안, 검증 방법을 커밋 본문과 ADR에 남기는 것을 규칙으로 삼았습니다. 외부 API 401을 사흘 동안 변수 하나씩 빼 가며 격리한 경험, 워커가 여럿인 환경에서 메모리 대신 파일 캐시를 고른 이유, 멈춰 있던 자동화 CI를 4개월 만에 발견한 일까지, 성공보다 판단의 근거를 남기려 합니다.

이 페이지의 모든 숫자에는 커밋, 파일, 실행 결과 출처가 있고, 팀 성과와 제 기여를 구분해 적었습니다.

K-OSP, 교내 오픈소스 포털 운영 중

2026년 2월부터 현재 · 팀 프로젝트(개발 2명, 디자인 1명) · 팀장

학생들의 GitHub 활동을 자동 수집해 랭킹, 칭호, 이력서로 바꿔 주는 서비스입니다. 전임 개발자가 떠난 뒤 6개 모듈(backend, harvester, challenge-service, common, rabbitmq, flyway)로 된 구조를 인수해, 운영과 기능 확장을 함께 해야 했습니다.

내가 맡은 것
칭호 시스템, 시즌 랭킹과 티어, 다중 이력서 API와 PDF·hwpx 출력, 학습자료, 팔로우, 약관 동의 정책, 커밋→Notion 자동 기록 CI. 백엔드 33, 프론트 58 커밋, Flyway 마이그레이션 35건, +20,045줄. MSA 구조 자체는 전임자 설계를 인수한 것으로 제가 설계하지 않았습니다.
스택
Java 17, Spring Boot 3.5, JPA, PostgreSQL + Flyway, Redis(Valkey), MongoDB, RabbitMQ, hwpxlib / Next.js 15, React 18, TypeScript, Tailwind 4 / Docker Compose, GitHub Actions

  1. 이력서 hwpx를 어디서 만들 것인가

    문제
    프론트에서 만들면 화면 미리보기와 실제 파일이 달라졌습니다.
    판단
    hwpxlib로 백엔드에서 생성하고, 미리보기는 실제로 내려받을 PDF 하나로 통일했습니다.
    결과
    미리보기와 파일이 일치. 글자 잘림은 페이지 절단 후보를 섹션 경계에서 항목 경계(data-pdf-cut)로 세분화해 강제 절단 5건을 0건으로. KOSP-Frontend fbe3502

  2. 배포 직후 502, 원인은 마이그레이션 번호 충돌

    문제
    배포하자마자 nginx 502. 로그는 "Found more than one migration with version 29".
    판단
    이미 적용된 V29와 제 V29가 같은 번호였습니다. 테스트 프로필이 Flyway를 끄고 H2 create-drop을 써서 CI가 잡지 못한 것을 확인하고, 적용된 쪽은 두고 제 파일을 V33으로 옮겼습니다.
    결과
    데이터 손실 없이 복구. CI가 초록이어도 운영과 다른 프로필이면 보장이 없다는 것을 배웠고, 테스트에서도 Flyway를 켜는 일을 다음 이슈로 남겼습니다. KOSP-Backend d0ce68b4

  3. 4개월 동안 아무도 모르게 멈춰 있던 자동화

    문제
    커밋마다 Notion에 작업 로그를 쌓는 CI가 7월부터 시크릿 오류로 실패하고 있었는데, 실패를 알리는 장치가 없었습니다.
    판단
    자동 집계는 "했다"는 남기지만 "왜"는 못 남깁니다. 그래도 멈춘 자동화는 더 나쁘다고 보고 둘 다 고쳤습니다.
    결과
    시크릿 형식 가드 추가, 누락분 16건 백필. 기록은 교수님 피드백으로 9월부터 주간 리포트(5부)로 옮겨 유지. .github/scripts
그 밖의 수정 기록
  • 초대 상세 500: 트랜잭션 밖 LAZY 접근 → 클래스 레벨 @Transactional(readOnly = true) (6696e841)
  • PDF 생성 실패: Tailwind 4의 oklch()를 html2canvas가 지원하지 않음 → html2canvas-pro로 전환 (a9047fc)

FarmLink, 충청권 농촌관광 체험 예약과 AI 추천 코스 2026.09 종료

2025년 9월부터 2026년 9월 · 팀 프로젝트(PM 1, 백엔드 2, 프론트 1) · 백엔드

농장 체험 예약과 주변 관광 코스 추천을 한 흐름으로 묶은 플랫폼입니다. 사용자 위치 50km 안에서 규칙 점수(거리 0.5, 특산 0.3, 여석 0.2)로 순위를 정하고, LLM은 추천 이유 문장만 만듭니다. ESG 점수와 11개 대분류 223개 조건 필터를 제공합니다.

내가 맡은 것
TourAPI 4종(관광지, 반려동물, 무장애, 의료) 연동, 추천 점수와 코스 생성, ESG 점수, 조건 카테고리 상수화, 파일 캐시, GitHub Actions 배포, 1,536줄 app.py 도메인 분할(38파일), 팀 규칙 문서. 본인 커밋 174건. 회원, 예약, 결제, 관리자 도메인은 다른 백엔드 팀원 담당.
스택
Python 3.10, Flask 3.1, SQLAlchemy, MySQL, PWA, 한국관광공사 TourAPI, 카카오맵, Naver CLOVA, pytest, GitHub Actions, PythonAnywhere

  1. 같은 401이 사흘 동안 네 가지 뜻이었다

    문제
    키 오타, 신청 누락, 활성화 대기, 주소 오류가 전부 같은 401로 보였고, 코딩 도구의 진단도 키 문제와 환경 문제 사이를 오갔습니다.
    판단
    코드, 환경변수, .env를 하나씩 빼고 브라우저에서 직접 호출해 "키 자체가 인증되는가"만 남겼습니다. 서비스 오류 코드가 없는 맨 401은 게이트웨이 미등록이었습니다.
    결과
    코드는 처음부터 맞았고, 활성화 뒤 95건을 받았습니다. 이후 외부 API 문제는 직접 호출로 먼저 격리합니다. README 트러블슈팅

  2. 캐시를 메모리도 DB도 아닌 파일에 둔 이유

    문제
    코스 카드마다 API를 2~4회 호출해 일일 한도 1,000건이 시연 중에 소진됐습니다.
    판단
    메모리 캐시는 워커 수만큼 효과가 나뉘고, DB 캐시는 팀원의 마이그레이션 영역을 건드립니다. 파일은 워커가 공유하고 재시작 후에도 남습니다. 좌표를 소수 2자리(약 1.1km)로 반올림하고, tempfile과 os.replace로 원자적으로 쓰고, 빈 응답은 짧은 TTL로 분리했습니다.
    결과
    한도 소진이 재발하지 않았습니다. 응답시간 개선 폭은 재지 못했습니다. fad523ca · ADR-0003

  3. 순위는 규칙이, 설명은 LLM이

    문제
    LLM이 코스 순위까지 정하면 왜 그 순서인지 설명할 수 없고 결과가 흔들립니다.
    판단
    순위는 거리, 특산, 여석 가중치의 규칙 점수로 정하고, LLM(CLOVA)은 추천 이유 문장만 생성하도록 역할을 나눴습니다.
    결과
    같은 입력에 같은 순위. 가중치는 PM이 직접 조정할 수 있게 상수로 분리. ADR-0002
